## Goal

แปลง idea, requirements, หรือ user feedback เป็น product specification, roadmap, และ user stories ทีชัดเจน

## Scope

ใช้เมื่อต้องการกำหนด product direction, features, user journey, และ metrics จาก input ทั่วไป

## Execute

### 1. Understand Input

> Goal: วิเคราะห์ product idea

1. อ่าน requirements, feedback, หรือ idea
2. ระบุ target users และ personas
3. ระบุ problems ทีจะแก้
4. ระบุ value proposition

### 2. Define Product Scope

> Goal: กำหนดขอบเขต product

1. ระบุ core features
2. ระบุ MVP scope
3. ระบุ out-of-scope
4. ระบุ success metrics

### 3. Build Product Spec

> Goal: เขียน product specification

1. Overview และ goals
2. User personas และ use cases
3. Feature list พร้อม priority
4. User stories รูปแบบ "As a [user] I want [feature] so that [benefit]"
5. Acceptance criteria
6. Metrics และ KPIs

### 4. Create Roadmap

> Goal: วางแผนการพัฒนา

1. แบ่ง phase: now, next, later
2. ระบุ dependencies ระหว่าง features
3. ประเมิน effort แบบ rough (S/M/L)
4. ใช้ `/report-table` สรุป roadmap

## Rules

### 1. User Centric

- เน้น user problem และ benefit
- ไม่เสนอ feature โดยไม่มี user หรือ metric
- ระบุ personas ชัดเจน

### 2. Measurable

- ทุก feature ควรมี metric หรือ acceptance criteria
- ระบุ KPIs ทีตรวจได้
- ไม่ใช้ vague goals

### 3. Pragmatic

- MVP ก่อนเสมอ
- ไม่ over-scope
- ระบุ out-of-scope ชัดเจน

## Expected Outcome

- product spec ครบถ้วน
- user stories พร้อม acceptance criteria
- roadmap แบ่ง phase
- metrics และ KPIs ชัดเจน
