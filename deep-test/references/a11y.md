# Deep Test — A11y Domain

Run accessibility tests — WCAG violations, keyboard navigation, screen reader semantics, color contrast (merged from `/test-a11y`)

Signals: `axe`/`jest-axe`/`@axe-core/*`, `pa11y` config, Lighthouse a11y audits, `.a11y.` specs, `@storybook/addon-a11y`

- Fixing findings → `/improve a11y` or `/deep-review-codebase` domain `review-accessibility`; motion/reduced-motion → `/improve uxui`

## 1. Detect

> Goal: find the a11y tooling and pick the scan mode

1. Detect: `axe-core`, `jest-axe`, `@axe-core/playwright`, `pa11y`, `@storybook/addon-a11y`, Lighthouse a11y category
2. Runner: axe in Playwright/Vitest → run the spec suite; pa11y → `bunx pa11y <url>`; site-wide → `/follow-tool-unlighthouse`; single page → `/follow-tool-lighthouse`

## 2. Run

> Goal: scan every route/component with manual checks

1. axe suite → run the spec normally
2. Ad-hoc on a running app → scan each route with `@axe-core/playwright` or `pa11y <url>`
3. Manual checks where tools fall short → keyboard-only walkthrough, focus order, zoom 200%, screen reader flow
4. Record violations with WCAG rule id + severity

## 3. Classify

> Goal: separate real violations from config noise

1. Real violation (missing label, contrast, focus trap, missing landmark) → source → `/resolve-errors` or `/improve a11y`
2. Wrong rule config / false positive → test → `/update-tests`
3. Scan env not ready (page did not load) → environment
4. Repeats ≥3 → stop + report

## 4. Report

> Goal: persist violations with WCAG refs

1. Persist → `.devin/temp/report/<workspace>/a11y-test-<time>.md` — violations per route/component with WCAG level (A/AA), severity (critical/serious/moderate/minor), element selector
2. All passing → `/run-verify`

## Rules

### 1. Rule Integrity

- Never disable axe rules without a justification in a config comment

### 2. Severity Gate

- Order by severity: critical/serious first — block merge if public-facing

### 3. Tools Are Not Enough

- Never rely on automated scans alone — axe covers ~40% of WCAG; flag the points that need manual checks (focus order, screen reader flow)

## Expected Outcome

- A11y violations per route/component with WCAG ref + severity
- Failures classified as source/test/environment
- Report persisted under `.devin/temp/report/`
