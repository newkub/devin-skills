## Goal

แปลง code, description, หรือปัญหาที่ผู้ใช้ให้มาให้เป็นสูตรคณิตศาสตร์ที่กระชับ เข้าใจง่าย และนำไปใช้ได้จริง

## Scope

ใช้สำหรับ:
- แปลง code/algorithm/description ที่อธิบายการคำนวณให้เป็น math formula
- ขอสูตรสำหรับปัญหาที่ user อธิบายโดยไม่มี code ให้แปลง

## Execute

### 1. Analyze Input

> Goal: ระบุประเภท input

1. ระบุ input type: `code`, `algorithm`, `description`, `problem`
2. ถ้าเป็น `code`/`algorithm`/`description` → ทำตาม Step 2a
3. ถ้าเป็น `problem` ที่ไม่มี code → ทำตาม Step 2b
4. ถ้า input ไม่ชัดเจน → ถาม user ก่อน

### 2a. Extract From Code Or Description

> Goal: สกัดตัวแปรและความสัมพันธ์

1. กำหนดตัวแปรด้วยสัญลักษณ์ที่กระชับ
2. ระบุความสัมพันธ์ระหว่างตัวแปร
3. ระบุเงื่อนไขและข้อจำกัด
4. ถ้ามีหลายสูตรที่เกี่ยวข้องกัน → จัดกลุ่มตามลำดับ

### 2b. Extract From Problem

> Goal: สกัดปัญหาเป็นตัวแปรและค่าที่ต้องการ

1. วิเคราะห์ปัญหาและบริบท
2. ระบุตัวแปรและค่าที่รู้
3. ระบุค่าที่ต้องการคำนวณ
4. ระบุขอบเขตและเงื่อนไขของปัญหา

### 3. Build Formula

> Goal: เขียนสูตรคณิตศาสตร์

1. เขียนสูตรหลักด้วย LaTeX: `$formula$` inline, `$$formula$$` block
2. ใช้สัญลักษณ์มาตรฐาน: `\sum`, `\prod`, `\int`, `\frac`, `\sqrt`, `\begin{cases}`
3. แปลง loop → `\sum`/`\prod`, condition → piecewise, recursion → recurrence
4. ถ้าขอสูตรจากปัญหา → อธิบายการคิด step-by-step ก่อนนำเสนอสูตร

### 4. Validate And Simplify

> Goal: ตรวจสอบความถูกต้อง

1. ทดสอบสูตรกับค่าตัวอย่าง
2. ตรวจสอบว่าผลลัพธ์ตรงกับ code/description/problem เดิม
3. ลดรูปสูตรให้กระชับที่สุด
4. ถ้าไม่ตรง → กลับไป Step 2

### 5. Report

> Goal: นำเสนอผลลัพธ์

1. แสดงสูตรหลักใน `$$...$$`
2. แสดงตารางสัญลักษณ์และความหมาย
3. แสดงตัวอย่างการคำนวณพร้อมผลลัพธ์
4. ระบุเงื่อนไขและข้อจำกัด

## Rules

### 1. Formula Standards

- ใช้ LaTeX notation: `$...$` inline, `$$...$$` block
- ใช้สัญลักษณ์มาตรฐาน: `\sum`, `\prod`, `\int`, `\frac`, `\sqrt`, `\leq`, `\geq`
- ตัวแปรใช้ตัวอักษรกรีกหรือละตินตามธรรมเนียม
- ถ้ามีหลายสูตรให้เลขกำกับ `(1)`, `(2)`

### 2. Quality

- สูตรกระชับที่สุดเท่าที่ทำได้
- มีตารางสัญลักษณ์เสมอ
- มีตัวอย่างการคำนวณอย่างน้อย 1 ตัวอย่าง
- ระบุเงื่อนไขและข้อจำกัด

### 3. No Over-Engineering

- ไม่สร้างสูตรที่ซับซ้อนเกินความจำเป็น
- ถ้าปัญหาง่าย → สูตรง่าย อธิบายสั้น
- รักษา semantics ของ input เดิม

## Expected Outcome

- สูตรคณิตศาสตร์ใน LaTeX ที่ถูกต้อง
- ตารางสัญลักษณ์และความหมาย
- ตัวอย่างการคำนวณพร้อมผลลัพธ์
- เงื่อนไขและข้อจำกัดที่ชัดเจน
